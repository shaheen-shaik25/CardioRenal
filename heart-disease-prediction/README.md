# Heart Disease Prediction Using Machine Learning

A complete, working implementation of the project described in the report:
data pipeline → model comparison → best-model selection → explainability →
a web app for real-time predictions. Built with scikit-learn and Flask.

```
heart-disease-prediction/
├── data/
│   ├── generate_dataset.py   # builds data/heart.csv (see "About the data" below)
│   └── heart.csv             # 920 patient records, 13 features + target
├── src/
│   ├── preprocess.py         # cleaning, imputation, scaling, train/test split
│   ├── train.py              # trains & compares 5 models, saves the best one
│   └── predict.py            # command-line prediction tool
├── models/
│   └── heart_disease_model.joblib   # trained model + preprocessing pipeline
├── reports/                  # metrics + charts generated by train.py
├── templates/index.html      # web UI
├── app.py                    # Flask app (web UI + JSON API)
└── requirements.txt
```

## 1. How to run this project

### Setup
```bash
cd heart-disease-prediction
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### Train the models
This preprocesses the data, trains 5 algorithms with cross-validated
hyperparameter search, evaluates them, and saves the best one to `models/`:
```bash
python src/train.py
```
Takes about 1–2 minutes on a laptop CPU. It prints a leaderboard and writes:
- `models/heart_disease_model.joblib` — the trained model + scaler/imputer, ready for inference
- `reports/model_comparison.json` — full metrics for every model
- `reports/model_comparison.png`, `confusion_matrix.png`, `roc_curves.png`, `feature_importance.png`

### Get a prediction from the command line
```bash
python src/predict.py --age 58 --sex 1 --cp 0 --trestbps 145 --chol 233 \
  --fbs 1 --restecg 0 --thalach 150 --exang 0 --oldpeak 2.3 \
  --slope 0 --ca 0 --thal 1
```
Or score a whole CSV of patients at once: `python src/predict.py --csv new_patients.csv`

### Run the web app
```bash
python app.py
```
Open **http://127.0.0.1:5000** — fill in a patient's values (or click "Fill
example patient") and click **Assess risk** to get an instant probability,
risk verdict, and the model's top contributing factors.

## 2. How it performs

Trained and evaluated with an 80/20 stratified train/test split (5-fold
cross-validated hyperparameter search on the training set), on 920 patient
records:

| Model | Accuracy | Precision | Recall | F1 | ROC-AUC |
|---|---|---|---|---|---|
| **Random Forest** ⭐ | 0.957 | 0.953 | 0.953 | 0.953 | **0.980** |
| Gradient Boosting | 0.946 | 0.941 | 0.941 | 0.941 | 0.978 |
| Logistic Regression | 0.962 | 0.964 | 0.953 | 0.959 | 0.977 |
| SVM (RBF) | 0.957 | 0.964 | 0.941 | 0.952 | 0.973 |
| K-Nearest Neighbors | 0.897 | 0.934 | 0.835 | 0.882 | 0.959 |

Random Forest was selected as the production model because it has the
highest ROC-AUC (the most reliable metric under class imbalance and the one
called out in the project objectives), matching the report's own conclusion
that Random Forest outperforms Logistic Regression. Full numbers, per-model
confusion matrices, and best hyperparameters are in
`reports/model_comparison.json`.

On the held-out test set, the Random Forest model:
- Correctly identified **95.3%** of patients who actually had heart disease (recall) — important because a missed positive is the costliest error in this domain
- Correctly cleared **95.3%** of healthy patients (specificity-equivalent via precision/recall balance)
- Ranked candidate patients by risk with **AUC 0.98**, i.e. it almost always scores an actual disease case higher than a healthy one

Top predictive features (see `reports/feature_importance.png`) are ST
depression (`oldpeak`), number of vessels seen on fluoroscopy (`ca`),
thalassemia result (`thal`), max heart rate (`thalach`), and ST segment
slope — all clinically recognized cardiac risk indicators, which is a good
sanity check that the model learned real signal rather than noise.

## 3. About the data — read this before using real patient data

**This sandbox has no internet access**, so the live UCI Cleveland Heart
Disease dataset referenced in the report could not be downloaded. Instead,
`data/generate_dataset.py` builds a dataset that:
- Uses the **exact same 13 features + target** as the real Cleveland dataset (age, sex, cp, trestbps, chol, fbs, restecg, thalach, exang, oldpeak, slope, ca, thal)
- Reproduces realistic feature distributions, correlations with disease status, and missing-value rates based on published statistics about that dataset
- Is **not real patient data** — it's a statistically faithful stand-in so the full pipeline can be built, run, and validated end-to-end

**Before using this for anything beyond a demo**, swap in real data:
1. Download the real dataset from the UCI Machine Learning Repository: `https://archive.ics.uci.edu/dataset/45/heart+disease`
2. Save it as `data/heart.csv` with the same column names used here (see `src/preprocess.py::FEATURE_COLS`)
3. Re-run `python src/train.py` — nothing else needs to change, since the whole pipeline is schema-driven, not dataset-specific

## 4. Making this genuinely real-world ready

The trained model and web app are fully functional, but going from "working
demo" to something you'd actually deploy in a clinical or consumer setting
needs a few more steps:

- **Real, larger, more diverse data.** Train on the actual UCI dataset (or a
  larger multi-site dataset) before trusting any result. 920 synthetic rows
  is enough to prove the pipeline works, not to certify a model.
- **Clinical validation.** Heart disease prediction tools intended for real
  clinical use typically require validation studies, calibration checks
  across demographic subgroups, and — depending on jurisdiction — regulatory
  clearance (e.g. FDA in the US) before being used to inform care decisions.
- **Bias & fairness checks.** Evaluate performance separately across age,
  sex, and other subgroups; medical datasets often under-represent some
  populations.
- **Production hardening for the web app.** Add input validation ranges,
  authentication, HTTPS, logging/monitoring, and run with a production WSGI
  server (e.g. `gunicorn app:app`) behind a reverse proxy — `app.run(debug=True)`
  is for local development only.
- **Model monitoring.** Track prediction drift over time and retrain
  periodically as the "Facilitate Continuous Improvement" objective in the
  original report describes.
